# Robo Slide Layout Catalog

Choose the layout from the question the slide must answer. Do not choose a layout because it looks attractive.

| Layout | Use when the slide must answer | Default structure |
|---|---|---|
| statement | What is the single most important idea? | one claim + one proof |
| split-story | What is the contrast or tension? | left/right or before/after |
| metrics | What changed numerically? | 2–4 metrics + one interpretation |
| comparison | How do options differ? | comparable rows/columns |
| process | How does it work? | 3–6 ordered stages |
| architecture | What connects to what? | layers, systems, flows |
| matrix | How should items be positioned? | 2×2 or scored grid |
| timeline | What happens when? | chronological milestones |
| dashboard | What is the operating state? | metrics + status + actions |
| demo | What should the audience notice in a product flow? | screen/action/result |

## Composition rules

- One slide = one governing message.
- The title should state the conclusion, not merely the topic.
- Reading titles alone should reveal the deck's argument.
- Evidence should occupy more visual area than labels.
- Use direct comparison when the audience must make a choice.
- Use process only when sequence matters.
- Use architecture only when relationships matter.
- Avoid grids of unrelated cards unless the content is genuinely parallel.
- Prefer 2–4 visual groups. More than 6 groups requires an explicit reason.
- If no archetype fits, create a new composition. Do not force content into a template.

## Robo Lab / Tech behavior

Use strong grid alignment, code-like metadata, restrained blue accents, and UI framing. Technical treatment must reinforce structure; it must not become decoration.
